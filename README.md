# 调度数据网批复单业务IP填充工具

打开一份《调度数据网接入地址批复单》，把「**本端业务IP地址**」列按「**策略名称**」自动算好填进去，另存成新文件。**原模板不会被改动。**

---

## 一、三步上手

1. **选批复单 + 填站点名** —— 默认已载入内置的批复单模板，也可点「浏览」选自己的 `.docx`；顶部「站点名称」填好后，本次导出会自动归档到历史台账。
2. **点「自动识别」** —— 程序穷举「业务模板 × 掩码位数」，拿批复单里已有的地址逐个打分，自动挑出最吻合的一套，并把**每张表的起始 IP** 一起填好。识别结果会弹出提示，如「28位掩码（备用模板）+ /28，32/32 行吻合」。
3. **看预览 → 导出** —— 右侧预览列出每行「策略名称 → 匹配业务 → 原值 → 将填入」，确认无误后点「**导出 Word 批复单**」。

就这三步，不需要理解任何 IP 规划细节。

## 二、界面长什么样

```
┌──────────────────────────────────────────────────────────────────────┐
│ 批复单 [内置模板.docx  ] [浏览…] [自动识别] [刷新预览]  业务模板▾ 配置│
├──────────────────────────┬───────────────────────────────────────────┤
│ 实时业务 │ 非实时业务     │ 每张纵密表的起始 IP                      │
│ 起始IP [10.20.1.0   ]    │ 第一接入网实时  [54.100.134.96] /28▾      │
│ ☑ 远动     7   8         │ 第一接入网非实时[54.100.135.96] /28▾      │
│ ☑ 保护     9   10        │ 第二接入网实时  [54.124.6.48  ] /28▾      │
│ ☑ PMU      5   6         │ 第二接入网非实时[54.124.7.48  ] /28▾      │
│ ☑ 网安     2             ├───────────────────────────────────────────┤
│ ☑ 稳控     3   4         │ 填充预览                                  │
│ ☑ 宽频装置  1   11       │ 纵密表|隧道|策略名称|业务|原值|将填入     │
```

**左侧**是业务偏移表（数据源，可增删改）；**右侧**是批复单填充（起始 IP + 实时预览 + 导出）。

## 三、计算规则

```
业务地址 = 起始 IP 前三段 . (基准 + 偏移)
```

**基准 = 起始 IP 的第四字节**，**偏移** = 左侧业务表里的 C 列 / D 列。

> 例：起始 IP = `54.100.134.96`，远动偏移 7、8，掩码 /28
> → 远动 1 网 = **54.100.134.103**，远动 2 网 = **54.100.134.104**
> → 批复单里写成 **54.100.134.103-104**

**注意：这是给单个业务分配一个 IP 地址，不是划分网段。** 掩码位数只用来标出该地址所属的网段信息（网络号、网关、广播范围）。

### 地址写法（与批复单原文一致）

| 情况 | 写法 |
|---|---|
| 单网 | `54.100.134.98` |
| 双网 | `54.100.134.103-104`（前三段相同，末位写范围） |
| 不连续 | `54.100.135.98、54.100.135.118` |

## 四、预览里的颜色

| 颜色 | 含义 |
|---|---|
| 🟢 绿色 | 原本空白、本次补填 |
| 🟠 橙色 | 原值会被覆盖 —— **说明配置与批复单不一致，请重点核对** |
| ⚪ 灰色 | 算出来与原值一致，无变化 |
| 🔴 红色 | 不会填入 |

红色又分两种，界面会写明：

- **「策略名未匹配」** —— 该策略名称没对上任何业务。要加规则，编辑 `ip_word.py` 顶部的 `POLICY_RULES`。
- **「XX（未启用/无偏移）」** —— 对上了，但该业务在左侧被取消勾选、或没填偏移。勾上并填偏移即可。

## 五、策略名称是怎么匹配业务的

关键词包含匹配，且**只在该表所属大类（实时 / 非实时）内匹配** —— 这一点很关键，因为实时大类的「网安」和非实时大类的「网络安全监测」是两个不同业务，跨大类匹配会导致填不进去。

| 策略名称 | 匹配到的业务 |
|---|---|
| 备调 / 地调 / 区调 远动 fes1~4 | 远动 |
| 区调PMU1 / PMU2 | PMU |
| 区调稳控 | 稳控 |
| 区调保护1 / 保护2 | 保护 |
| 区调内网管控（网安） | 网安 |
| 区调电量、地调电量 | 电量 |
| 区调保信 | 保信 |
| 区调光功率 / 风功率 | 光功率 / 风功率 |
| 区调水情 | 水情 |
| 区调同步时钟、区调安控1/2 | 同步时钟、安控（默认停用，需自行分配偏移） |

## 六、自动识别

点「自动识别」后，程序会：

1. 穷举「业务模板（/27、/28）× 掩码位数（25~30）」共 12 种组合；
2. 用每张表**已有的地址**逐个试算并打分；
3. 选出吻合行数最多的组合，同时把每张表的起始 IP 和掩码一起填好。

对你的批复单，识别结果是 **28位掩码（备用模板）+ /28 掩码，32/32 行完全吻合**。

- 若表里没有已填地址可供比对，会提示你手动填写。
- 若最佳组合吻合度偏低，会弹窗警告并列出橙色行，方便人工核对。

## 七、批量站点

第二个页签，每行一个站点，列为「站点名称 + 每张纵密表的起始 IP」。点「批量导出批复单」，会为每个站点生成一份填好的 `.docx`，文件名 = 站点名，统一保存到指定文件夹。起始 IP 留空则沿用「批复单填充」页的设置。

## 八、历史台账（查询与查重）

每次导出都会自动归档到程序目录下的 `history.db`（SQLite），新增「**历史记录**」页签可查。

### 归档了什么

一次导出 = 一条**批次**记录（站点、时间、用的模板、掩码、输出文件），
外加该次算出的**每一条地址明细**（纵密表、大类、策略名称、业务、网别、偏移、业务地址、所属网段、网关、起始 IP、原值）。

同一 IP 在同一批次内只记一条 —— 批复单里「备调远动fes1~4、地调远动fes1~2、区调远动fes1~4」十来行都写同一个 `103-104`，不会记十遍。

### 怎么查

| 筛选项 | 说明 |
|---|---|
| 关键词 | 同时匹配 IP、业务、策略名称、站点、纵密表名 |
| 站点下拉 | 从历史里自动收集，选一个只看该站点 |
| 业务下拉 | 只看某个业务（如只看「远动」的历次分配） |
| 时间范围 | 近 7 天 / 近 30 天 / 近一年 / 全部 |

上方表格列出批次，点一行，下方就显示该批次的全部地址明细。

### 分配时自动查重（最实用的一环）

预览表格里多了一列「**历史占用**」，每行实时标注：

| 提示 | 含义 |
|---|---|
| ⚠ 已被 XX 占用 | 该地址在台账里属于别的站点 —— **撞地址了，请核对起始 IP** |
| 本站已记录 | 本站此前导出过，属正常重复导出 |
| 新占用 | 台账里没有，本次首次分配 |

点「导出」时若发现与其它站点冲突，会弹窗列出冲突明细（最多 12 条），
点「否」可返回修改起始 IP，点「是」仍然继续导出。

批量导出时也会逐个站点查重，冲突会在完成后的提示里汇总列出，但不阻断整批。

### 台账维护

- **删除批次**：选中上方的批次行，点「删除选中批次」，连带明细一起删除。
- **清空台账**：点「清空台账」，会二次确认。
- **导出 Excel**：点「导出台账 Excel」，把全部历史导出成 14 列的表格，方便在 Excel 里筛选分析。
- **查重复地址**：点「查重复」，列出台账里被**多个站点**占用的地址 —— 用来定期体检。

> `history.db` 就在程序目录（打包后与 exe 同级），直接拷贝即可备份。

## 九、打包成 EXE

双击 **`BUILD.bat`**，等 3~5 分钟，产物为 `dist\IPAddressTool_PySide6.exe` 或 `dist\IPAddressTool_PySide2.exe`
（取决于打包时装的是哪种 Qt 绑定，约 70 MB，单文件、无黑框，拷到任意 Windows 电脑即可用，**对方不需要装 Python**）。

> 前提是电脑上装了 Python 3.8 以上（安装时务必勾选 "Add Python to PATH"）。
> 首次打包会自动建虚拟环境，并按系统版本装 PySide6 或 PySide2、openpyxl、
> python-docx，以及 PyInstaller。

**关键：必须在目标机器上打包。** 打包时会自动检测当前装的是哪种 Qt 绑定，
把对应的 Qt 运行库打进去。在 Win10 上打的包拷到 Server 2008 上依然会报
DLL 加载失败 —— 因为打进去的是 Qt 6 的库。

不想打包就双击 **`START.vbs`**，自动装依赖后直接启动。

## 十、命令行模式

不装图形界面库也能用（`pip install openpyxl python-docx` 即可）：

```bash
# 自动识别 + 导出（推荐）
python cli.py --word 批复单.docx --auto -o 批复单_已填.docx

# 只看预览，不导出
python cli.py --word 批复单.docx --auto

# 只填空白格
python cli.py --word 批复单.docx --auto --word-only-empty -o 批复单_已填.docx

# 手动指定各表起始 IP
python cli.py --word 批复单.docx \
    --word-base "省调第一接入网实时纵密参数=54.100.134.96,省调第一接入网非实时纵密参数=54.100.135.96" \
    -o 批复单_已填.docx
```

命令行还保留了业务地址计算与 Excel/CSV 导出能力，供需要时用：

```bash
python cli.py --realtime 10.20.1.160 --nonrealtime 10.20.2.160
python cli.py --realtime 10.20.1.160 --nonrealtime 10.20.2.160 -o 业务地址表.xlsx
```

## 十三、老系统支持：Windows Server 2008 / Win7

### 症状

在 Windows Server 2008、2008 R2 或 Windows 7 上启动，报：

```
ImportError: DLL load failed while importing QtCore:
             The specified procedure could not be found
```

**DLL 文件其实在，是加载不了。**

### 根因

PySide6 基于 **Qt 6**，而 Qt 官方在 Qt 6 中**彻底放弃了对 Windows 7 / 8.x 的支持**：

| Qt 版本 | 最低 Windows |
|---|---|
| Qt 6 | **Windows 10 1809 或更高** |
| Qt 5.15 | Windows 7 SP1 |

Qt 6 的 DLL 链接了 Win10 才有的系统 API。在老系统上加载时，
导入表里找不到这些入口点，于是报 ERROR_PROC_NOT_FOUND（「找不到指定的程序」）。

**这不是本项目的问题，是 Qt 6 的硬性系统要求，无解，只能换 Qt 5。**

### 解决办法：用 PySide2（Qt 5）

本项目的代码**同时兼容 PySide6 和 PySide2**，无需改任何业务代码。
运行时由 `qt_compat.py` 自动挑选可用的绑定：

```
PySide6 (Qt 6)  ->  Windows 10 / 11
PySide2 (Qt 5)  ->  Windows 7 SP1 / Server 2008 R2
PyQt5   (Qt 5)  ->  兜底
```

项目里用到的 Qt 枚举（如 `Qt.AlignCenter`、`QMessageBox.Yes`）
在两个版本里写法一致，所以切换是无感的。

### 你的系统能不能跑

**先确认版本号**（此电脑 → 属性）：

| 系统 | 内核 | 能否运行 | 说明 |
|---|---|---|---|
| Windows 10 / 11 | NT 10.0 | ✅ | 用 PySide6 |
| Server 2016 / 2019 / 2022 | NT 10.0 | ✅ | 用 PySide6 |
| **Server 2008 R2** | NT 6.1 | ✅ | **用 PySide2，需 Python 3.8** |
| Windows 7 SP1 | NT 6.1 | ✅ | 用 PySide2 |
| **Server 2008（非 R2）** | NT 6.0 | ❌ | 见下方说明 |
| Windows 8 / Server 2012 | NT 6.2 | ✅ | 用 PySide2 |

> **Server 2008 原版（NT 6.0，Vista 内核）无法运行。**
> Python 3.8（最后一个支持 Win7 SP1 的版本）在 NT 6.0 上装不了；
> PySide2 也要求 Win7 SP1。
> 这种机器建议升级到 Server 2008 R2 或更高，或换一台机器跑本工具。

### 操作步骤（Server 2008 R2 / Win7）

1. **装 Python 3.8**（最后一个支持 Win7 / Server 2008 R2 的版本）
   <https://www.python.org/downloads/release/python-3810/>
   选 `Windows x86-64 executable installer`，务必勾选 **Add Python to PATH**

2. **装依赖** —— 双击 `INSTALL.bat`，它会：
   - 检测你的 Windows 内核版本
   - NT 6.1 → 自动装 **PySide2**；NT 10.0+ → 装 **PySide6**
   - 顺带处理 lxml 的 wheel 问题（见第十四章）

3. **确认绑定** —— 命令行运行：

   ```bash
   python qt_compat.py
   ```

   期望输出 `Binding : PySide2` 且 `Qt : 5.15.x`。

4. **启动** —— 双击 `START.vbs`

### 强制指定绑定

设置环境变量即可覆盖自动选择：

```bash
set QT_BINDING=PySide2
python app_gui.py
```

排查时很有用 —— 可以对比两个绑定下的表现。

### 打包时的注意事项

在**目标系统**（即那台老服务器）上执行打包，
PyInstaller 会顺带把正确的 Qt 5 运行库打进去。
生成的 exe 可拷到同版本的其他机器上运行。

> 反过来不行：在 Win10 上用 PySide6 打的包，拷到 Server 2008 上仍然是同样的 DLL 错误。
> **必须在目标系统上装依赖并打包。**

## 十四、依赖安装失败：Microsoft Visual C++ 14.0 required

打包或首次运行时若看到红字：

```
error: Microsoft Visual C++ 14.0 or greater is required
ERROR: Failed building wheel for lxml
```

**这不是程序的问题。** lxml 是 python-docx 的底层依赖，pip 本该直接下载
Windows 预编译包（wheel），但没找到匹配你 Python 版本的 wheel，就退回去
用 C 源码编译 —— 而你机器上没有 C++ 编译器。

### 三种成因与对策

| 成因 | 表现 | 对策 |
|---|---|---|
| **pip 太旧**（最常见） | 读不懂新版 wheel 标签 | 先升级 pip，十有八九就好 |
| **Python 太新** | 如 3.15，lxml 还没出对应 wheel | 换 Python 3.11 / 3.12 |
| **确实没有 wheel** | 32 位或极冷门版本 | 装 C++ 生成工具，或换 Python |

lxml 官方 wheel 实际覆盖 CPython 3.8～3.15，所以**绝大多数情况只是 pip 太旧**。

### 一键修复

双击 **`INSTALL.bat`**，或命令行运行：

```bash
python install_deps.py
```

它会依次做四件事，并给出纯 ASCII 的中文友好报告：

1. **升级 pip** —— 这一步通常就解决了
2. **只装 wheel**（`--only-binary=:all:`）—— 找不到 wheel 就立刻报错，不再傻乎乎去编译
3. **lxml 逐个版本回退** —— 从 6.1.3 往下试，挑一个你的 Python 有 wheel 的版本
4. **逐项验证** —— PySide6 / openpyxl / python-docx / lxml / 程序入口，全过才算装好

万一全失败，报告会明确告诉你是哪种成因，并给出对应方案（换 Python 3.11/3.12
或装 C++ 生成工具）。

> 手动兜底：
> ```bash
> python -m pip install --upgrade pip
> python -m pip install --only-binary=:all: -r requirements.txt
> ```

## 十五、启动问题排查

### 先说最常见的坑：批处理乱码

如果双击 bat 后满屏「不是内部或外部命令」并伴随乱码，**这是 bat 文件编码问题，不是程序问题**。

中文 Windows 的 cmd 按 GBK 解析批处理文件，而 UTF-8 编码的中文被错误解码后会**破坏换行结构**，把每行命令切碎。
`chcp 65001` 救不了 —— cmd 是读完整个文件才执行 chcp 的，解析时已经坏了。

本项目已规避：三个 bat 全部是**纯 ASCII 英文 + CRLF 换行**，任何代码页下都不会乱码。
若你自行编辑 bat，请务必另存为 ANSI/GBK 编码，且不要写中文。

### 三种启动方式，任选其一

| 文件 | 说明 |
|---|---|
| **`START.vbs`**（推荐） | 双击即可，**完全绕过 cmd**，不受编码影响。出错直接弹窗说明原因，找不到 Python 会给出安装地址。 |
| `START.bat` | 带控制台启动，能看到完整过程和报错，出错会暂停。 |
| `CHECK.bat` | 只做环境体检不启动程序，逐项报告 Python / 依赖 / 模块 / 入口 / 模板 / 数据库。 |

> 建议先用 `CHECK.bat` 确认环境，再用 `START.vbs` 日常启动。

### 打包后的 exe 没反应 → 跑诊断版

`BUILD.bat` 会同时生成两个 exe：

| 文件 | 用途 |
|---|---|
| `dist\IPAddressTool.exe` | 正式版，无黑框，日常使用 |
| `dist\IPAddressTool_Diag.exe` | **带黑框**，双击无反应时用它看完整报错 |

### 查 error.log

程序崩溃时自动把完整堆栈写入程序目录（打包后为 exe 同级目录）的 `error.log`，
含时间、版本、运行模式、Python 版本与完整堆栈。把文件内容发来即可定位。

### 常见原因速查

| 现象 | 原因 / 处理 |
|---|---|
| bat 满屏「不是内部或外部命令」+ 乱码 | bat 编码问题，见上文。用 `START.vbs` 绕过 |
| 双击 exe 毫无反应 | 跑 `IPAddressTool_Diag.exe` 看报错 |
| `ModuleNotFoundError: PySide6` | 依赖没装好，重跑 `START.bat` 或 `BUILD.bat` |
| 提示缺 Qt platform plugin | 杀软拦截了 Qt 动态库，加白名单后重新打包 |
| 双击 .py 一闪而过 | 用 `START.bat` 或 `START.vbs`，别直接双击 py 文件 |
| 打包报 icon / version 错误 | 删掉 spec 里 `icon=` 与 `version=` 两行即可，不影响功能 |
| `python` 不是内部或外部命令 | Python 未安装，或未勾选 Add Python to PATH |
| `Microsoft Visual C++ 14.0 required` | lxml 在编译而非装 wheel，见下章，跑 `INSTALL.bat` |
| `DLL load failed while importing QtCore` | Qt 6 跑在老系统上，见第十二章，改用 PySide2 |
| `'NoneType' object has no attribute 'write'` | 旧版缺陷，已修复；Qt 加载失败被掩盖，现给出可读诊断 |

## 十六、用 GitHub 托管与云端打包

### 先说结论：GitHub 能做什么、不能做什么

| 用途 | 能否用 GitHub |
|---|---|
| 代码备份、版本管理、跨机器同步 | ✅ 完全可以，推荐 |
| 在云端自动打出 **Win10 版** exe | ✅ 可以，Actions 免费 |
| 在云端自动打出 **Server 2008 / Win7 版** exe | ⚠️ 理论上可行，但**必须在目标机实测** |

GitHub 官方的 Windows 运行器是 **Server 2019 / 2022 / 2025**，都是 NT 10.0。
但关键在于：**构建时用哪个 Python + 哪个 Qt 绑定，才决定产物能跑在哪**。

- GitHub runner + Python 3.8 + PySide2 → 打进去的是 Qt 5 → **理论上可跑 Win7 / Server 2008 R2**
- GitHub runner + Python 3.11 + PySide6 → 打进去的是 Qt 6 → 只能跑 Win10 1809+

> 风险提示：PyInstaller 的引导程序（bootloader）本身也有 Windows 版本要求，
> 云端构建的结果我无法在 Linux 沙盒里验证。**请务必拷到目标机器上实测。**
> 若云端版跑不起来，回到「在目标机器上本地打包」这条最稳的路。

### 一、上传到 GitHub

项目里已备好 `.gitignore`（会自动排除 `.venv`、`build`、`dist`、
`history.db`、`error.log`、`__pycache__` 等，不会把垃圾和台账传上去）。

```bash
cd ip_allocator

git init
git add .
git commit -m "调度数据网批复单业务IP填充工具 v1.1"

# 在 GitHub 网页上新建一个空仓库（不要勾选 README / .gitignore）
git remote add origin https://github.com/你的用户名/你的仓库名.git
git branch -M main
git push -u origin main
```

之后每次改动：

```bash
git add .
git commit -m "说明改了什么"
git push
```

> 仓库建议设为 **Private**。历史台账和批复单模板里可能有内网 IP 和站点名。

### 二、用 GitHub Actions 自动打包

项目已带好 `.github/workflows/build-exe.yml`，推上去就能用。

**触发方式**：仓库页面 → **Actions** → 左侧选 **Build EXE** → 右上角
**Run workflow**，然后选：

| 选项 | 产物 | 适用系统 |
|---|---|---|
| `legacy` | `IPAddressTool_PySide2.exe` | Win7 SP1 / Server 2008 R2 及更高 |
| `modern` | `IPAddressTool_PySide6.exe` | Win10 1809 / Server 2016 及更高 |
| `both` | 两个都要 | — |

跑完在 **Actions → 对应的运行记录 → Artifacts** 里下载。

打 tag 也会自动触发（如 `git tag v1.1 && git push --tags`）。

### 三、⚠️ 重要更正：Python 版本

之前我说「Server 2008 R2 用 Python 3.9」，**这是错的**。

Python 官方文档明确写了：

> Python 3.9.0 ... The installer now also actively disallows installation
> on Windows 7. Python 3.9 is incompatible with this unsupported version of Windows.

**Python 3.8 才是最后一个支持 Windows 7 / Server 2008 R2 的版本。**

所以老系统的正确组合是：

| 组件 | 版本 | 原因 |
|---|---|---|
| Python | **3.8** | 最后一个支持 Win7 SP1 的版本 |
| Qt 绑定 | **PySide2** | Qt 5 支持 Win7 SP1；PySide2 的 wheel 覆盖到 Python 3.9 |
| PyInstaller | 5.x | 6.x 要求 Python 3.8+，老机器上用 5.x 更稳 |

本项目 `install_deps.py` 和 `qt_compat.py` 的诊断文案都已按此更正。

### 四、如果云端版在老机器上跑不起来

按顺序排查：

1. 看目标机器程序目录下有没有生成 `error.log`，里面写了每个 Qt 绑定的真实错误
2. 确认下载的是 `PySide2` 那个 artifact，不是 `PySide6` 的
3. 还是不行就**在目标机器上本地打包** —— 这是唯一 100% 可靠的路径：

   ```bash
   python install_deps.py     # 会自动选 Python/Qt 组合
   BUILD.bat
   ```

### 五、换机器继续开发

```bash
git clone https://github.com/你的用户名/你的仓库名.git
cd 你的仓库名
INSTALL.bat     # 装依赖
START.vbs       # 运行
```

`.gitignore` 已排除 `history.db`，所以**台账不会跟着代码走**。
想换机器继续用同一份台账，手动拷贝 `history.db` 即可。

## 十七、常见问题

**Q：为什么有的行显示「未启用/无偏移」？**
该业务在左侧被取消勾选，或没填偏移。勾上并填偏移就会参与填充。批复单里的「区调同步时钟」「区调安控1/2」默认就是这样 —— 内置模板没给它们分配偏移，需要你按实际情况补。

**Q：预览里出现橙色行怎么办？**
橙色表示算出来的值与批复单原有值不同。先用「自动识别」重试；若吻合度仍偏低，说明该批复单的偏移规则与内置模板不同，请手动调整左侧业务偏移表。

**Q：批复单里某个策略名称没被识别？**
编辑 `ip_word.py` 顶部的 `POLICY_RULES`，加一行 `("业务名", ["关键词1", "关键词2"])`。注意业务名要和左侧业务表里的名称一致。

**Q：想换一份自己的批复单模板？**
点「浏览」选你的 `.docx`。只要表格里有「策略名称」和「本端业务IP地址」两列，程序就能自动识别出来，几张表都行。

**Q：杀毒软件报毒？**
PyInstaller 打包的程序常被误报，加白名单即可。源码全在项目里，可自行审查。

**Q：exe 有多大？**
约 70 MB（含 Qt 运行时）。已用 `PySide6-Essentials` 精简版并排除了大量无用 Qt 模块。
